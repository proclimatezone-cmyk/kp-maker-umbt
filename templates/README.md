# Шаблоны КП

## kp-new.docx

Новый вид КП, подготовленный из `КП шаблон 01.08.26.docx` (версия от 31.07.2026).
Исходный файл не менялся — это его копия с добавленными метками.

Что отличается от исходника:

- `№ 310726-01` → `№ {cp_number}`
- `Дата: 31.07.2026 г` → `Дата: {cp_date}`
- удалён отдельный фрагмент `MN` после номера: номер приходит из приложения
  целиком, а разорванный на части текст docxtemplater не распознаёт

Метки продублированы: Word хранит этот текстовый блок дважды —
в `mc:Choice` для современных версий и в `mc:Fallback` для старых.
Обе копии должны меняться одинаково, иначе в части редакторов Word
пользователь увидит старое значение.

### Метки

| Метка | Что подставляется |
|---|---|
| `{cp_number}` | Номер КП: дата + порядковый + инициалы менеджера |
| `{cp_date}` | Дата КП |
| `{#items}…{/items}` | Строка таблицы позиций, повторяется по числу позиций |
| `{category}` `{model}` `{qty}` `{price}` `{sum}` | Поля позиции |
| `{total_label}` `{total_value}` | Строка итога; подпись зависит от базиса поставки |
| `{#terms}{label}`…`{value}{/terms}` | Строка блока условий, повторяется |

Скобки одинарные — так работает `docxtemplater`. Двойные, как в шаблоне
для Google Slides, он разбирает как вложенные и падает с ошибкой
`duplicate_close_tag`.

### Что было перестроено

Таблиц позиций в исходнике две — по одной на страницу, с тремя строками-
образцами в каждой. Количество позиций заранее неизвестно, поэтому вторая
таблица удалена, а первая размечена одной повторяющейся строкой: Word сам
перенесёт её на следующую страницу, когда строки перестанут помещаться.
Строка «Итого» перенесена из второй таблицы в первую.

Блок условий в исходнике — четыре строки с фиксированными подписями, причём
последняя подписана «Условия оплаты», хотя содержит срок действия КП, а строки
про 100% предоплату нет вовсе. Теперь это одна повторяющаяся строка, а сами
пункты приходят из `src/lib/delivery-terms.ts`: для склада и заказа их пять,
для CIP и DDP — шесть.

Места под заказчика и контакты менеджера в этом виде КП не предусмотрены —
так и задумано.

## kp-old.docx

Старый вид КП, подготовленный из `КП шаблон UMBT.docx` (лого UMBT, фото
здания, серая шапка таблицы, лого «Midea Building Tech.» в строке «Итого»).
Раньше собирался через Google Slides — медленно, риск таймаута на
Hobby-плане, Word-версии не было вовсе. Теперь та же сборка, что и у
`kp-new.docx` (`buildKpDocx()` с другим `templatePath`), стабильно и с
Word-версией.

Исходник — 3 копии одной страницы подряд (letterhead + таблица + условия,
затем то же самое ещё дважды, с 5 и с 2 строками-образцами — расчёт на
объект с большим числом позиций, где таблица не влезает на страницу).
Оставлена только первая копия, остальные две страницы удалены целиком —
как и в `kp-new.docx`, Word сам перенесёт разросшуюся таблицу дальше.

### Метки

| Метка | Что подставляется |
|---|---|
| `{cp_number}` `{cp_date}` | Номер и дата КП |
| `{#items}…{/items}` | Строка таблицы позиций |
| `{%image}` `{category}` `{model}` `{qty}` `{price}` `{sum}` | Поля позиции — здесь «Наименование» и «Модель (01)» разные колонки (в отличие от kp-new, где они объединены) |
| `{price_label}` `{sum_label}` | Шапка денежных колонок: `getMoneyLabels()`, тот же расчёт, что и в интерфейсе («Цена у.е.» / «Цена CIP, у.е.» / «Цена СУМ» и т.п.) |
| `{total_value}` | Значение строки «Итого:» — подпись «Итого:» и лого статичные, из исходника |
| `{#termLines}{.}{/termLines}` | Пронумерованные строки условий — `buildTermsLines()`, тот же текст, что уже печатается для kp-new (там же, но строкой в таблице, а не абзацем) |

Для доп. работ (`isAdditional`) название кладётся в `category`, а не в
`model` — здесь это разные колонки, «Монтаж и пусконаладка» должен идти в
«Наименование», а не в «Модель (01)» (`src/lib/docx-kp.ts`).

## contract.docx

Договор поставки, подготовленный из `template doc .docx`. Исходник не менялся.

| Метка | Что подставляется |
|---|---|
| `{contract_number}` `{contract_date}` `{valid_until}` | Номер, дата, срок действия |
| `{spec_number}` | Номер спецификации |
| `{buyer_name}` `{buyer_director}` `{buyer_address}` `{buyer_inn}` | Покупатель |
| `{buyer_account}` `{buyer_mfo}` `{buyer_bank}` | Банковские реквизиты покупателя |
| `{total_in_words}` `{vat_amount}` | Пункт 3.1: сумма прописью и НДС |
| `{#rows}…{/rows}` | Строка спецификации |
| `{index}` `{name}` `{unit}` `{qty}` `{price}` `{total}` `{vat}` `{withVat}` | Поля строки |
| `{total_net}` `{total_vat}` `{total_gross}` | Строка «Итого» |

Реквизиты поставщика оставлены текстом: они не меняются.

### Что чинилось в исходнике

Word искрошил текст на фрагменты по истории правок: номер договора лежал
восемью кусками (`ДОГОВОР`, ` `, `№ `, `UZ`, `41`, `/`, `2`, `6`), дата —
одиннадцатью. Искать по ним подстрокой невозможно, поэтому замена идёт
через `tools/docx-replace.py`: текст абзаца склеивается, подстрока ищется
в склейке, а замена кладётся целиком в первый задетый фрагмент.

Адрес покупателя и его ИНН в исходнике слиплись в одну строку без
переноса — «…ул. Фуркат 1 тор, дом 5ИНН: 300 994 568». Разведены.
ИНН там же записан через неразрывный пробел, поэтому обычным поиском
не находился.
